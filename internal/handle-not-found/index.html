Go の NotFound 実装パターン解説

標準ライブラリと主要 OSS の実装を調査し、Go における「見つからなかった」を表現する方法を整理する。

はじめに

Go のエラー処理は、Go 1.13 で追加された errors.Is / errors.As を中心に設計されることが多い。 しかし「見つからなかった」という状況は、エラーとして返すだけが必ずしも正解ではない。

本章では、標準ライブラリと主要 OSSの実装を典拠に、 エラー型として表現するパターン、エラー型を使わないパターン、インターフェース層での契約、 そして実際の選択指針をまとめる。

1. エラー型を使う表現

大半のライブラリは「見つからなかった」ことをエラー値として返す。 その中でも、センチネル（単一の値）と型付きエラー（メタデータを持つ構造体）の 2 系統が基本となる。

1.1 センチネルエラー errors.Is

最もシンプルで、Go エコシステムでも最も広く使われているパターン。 パッケージレベルで var ErrXxx = errors.New("...") を定義し、 errors.Is で判定する。 

var ErrNotFound = errors.New("not found")

if errors.Is(err, ErrNotFound) {
    // 見つからなかった
}

標準ライブラリの例: database/sql.ErrNoRows、os.ErrNotExist、io/fs.ErrNotExist、io.EOF。

OSS の例: gorm.ErrRecordNotFound、mongo.ErrNoDocuments、redis.Nil。

センチネルはエラー連鎖の中に %w でラップされていても errors.Is で検出できる。 これが Go 1.13 以降のデファクト・スタンダードである。

参照: database/sql.ErrNoRows, os.ErrNotExist, io.EOF, gorm.ErrRecordNotFound, mongo.ErrNoDocuments, redis.Nil

1.2 型付きエラー errors.As

リソース名や ID などのメタデータを含めたい場合、構造体としてエラーを定義する。 errors.As で型を取り出し、フィールドにアクセスする。 

type NotFoundError struct {
    Resource string
    Name     string
}

func (e *NotFoundError) Error() string {
    return fmt.Sprintf("%s %q not found", e.Resource, e.Name)
}

var nf *NotFoundError
if errors.As(err, &nf) {
    fmt.Println(nf.Resource, nf.Name)
}

OSS の例: ent は NotFoundError として生成される。 k8s.io/apimachinery/pkg/api/errors は StatusError に Reason や Details を持つ。

型付きエラーを fmt.Errorf("...: %w", err) でラップしても errors.As は連鎖をたどって取り出せる。

参照: ent/entc/gen/template/base.tmpl (NotFoundError), k8s.io/apimachinery/pkg/api/errors/errors.go (StatusError, NewNotFound)

1.3 errors.Is を拡張する Is メソッド

errors.Is は、エラー連鎖をたどりながら等価判定を行う。 連鎖上のエラーが Is(target error) bool メソッドを実装していれば、 その結果も尊重される。

これにより、型付きエラーが「私は ErrNotFound と等価です」と宣言できる。 

func (e *NotFoundError) Is(target error) bool {
    return target == ErrNotFound
}

// 利用例
err := NewNotFoundError("user", "123")
errors.Is(err, ErrNotFound) // true

標準ライブラリの例: syscall.Errno.Is は ENOENT を fs.ErrNotExist と等価だと判定する。 同様に EACCES / EPERM は fs.ErrPermission と等価である。 

errors.Is(syscall.ENOENT, fs.ErrNotExist)   // true
errors.Is(syscall.EACCES, fs.ErrPermission) // true
注意: Is メソッドは「等価性」を宣言するためのものである。 フィールド（Resource や ID）を確認したい場合は、errors.As で型を取り出して判定する。 Is メソッド内でフィールドを比較するのは、errors.As が標準化される前（Go 1.13 以前）に見られた旧実装である。

参照: syscall/syscall_unix.go (Errno.Is), errors/wrap.go (errors.Is)

1.4 エラーコード / Fault 分類

AWS SDK for Go v2 / smithy では、エラーが ErrorCode() と ErrorFault() を持つ。 ErrorCode はエラーの種別を表す文字列、ErrorFault はクライアント起因かサーバー起因かを分類する。 

type ErrorFault int

const (
    FaultUnknown ErrorFault = iota
    FaultClient
    FaultServer
)

func (e *NotFoundError) ErrorCode() string { return "NotFoundError" }
func (e *NotFoundError) ErrorFault() ErrorFault { return FaultClient }

このパターンは、マイクロサービスや外部 API との連携でエラーを分類したい場合に有効である。

参照: aws-sdk-go-v2/service/dynamodb/types/errors.go (ResourceNotFoundException 等), smithy-go

1.5 自己申告型エラー

エラー型が NotFound() bool のようなメソッドを持つことで、 独自のエラー型であっても統一的に NotFound 判定に参加できる。 

type NotFoundReporter interface {
    error
    NotFound() bool
}

func (e *NotFoundError) NotFound() bool { return true }

これは明確な OSS 標準というよりは、複数の独自エラー型を横断的に判定したい場合の慣用的なパターンである。

1.6 MaskNotFound

ent の MaskNotFound と同じく、NotFound エラーをあえて nil に変換する。 「無い」ことを正常系として扱いたい場合に使う。 

func MaskNotFound(err error) error {
    if IsNotFound(err) {
        return nil
    }
    return err
}

参照: ent/entc/gen/template/base.tmpl (MaskNotFound)

1.7 低レイヤーエラーコード → ドメインエラー

syscall.Errno.Is が ENOENT を fs.ErrNotExist にマッピングするのと同じように、 低レイヤーのプロトコル固有エラーをドメイン層の NotFound エラーに変換する。

lib/pq の例: PostgreSQL の SQLSTATE 42P01（undefined_table）は、 テーブルが存在しないことを表す。これを NotFoundError に変換する。 

func MapPQError(err error) error {
    var pqErr *pq.Error
    if !errors.As(err, &pqErr) {
        return err
    }

    switch pqErr.SQLState() {
    case "42P01": // undefined_table
        return fmt.Errorf("pq %s: %w", pqErr.SQLState(),
            NewNotFoundError("table", pqErr.Table))
    default:
        return err
    }
}

参照: syscall/syscall_unix.go (Errno.Is), lib/pq/error.go (*Error.SQLState)

1.8 HTTP ステータスへの変換

ドメイン層の NotFound エラーを HTTP レイヤーで 404 に変換する。 k8s.io/apimachinery の StatusError は生成時に http.StatusNotFound を含める。 

func ToHTTPStatus(err error) int {
    switch {
    case errors.Is(err, ErrNotFound),
        errors.Is(err, sql.ErrNoRows),
        errors.Is(err, fs.ErrNotExist),
        errors.Is(err, redis.Nil):
        return http.StatusNotFound
    default:
        return http.StatusInternalServerError
    }
}

参照: k8s.io/apimachinery/pkg/api/errors/errors.go (NewNotFound は http.StatusNotFound を含む), net/http/server.go (http.NotFound)

2. エラー型を使わない表現

必ずしも「見つからない」をエラーとして扱う必要はない。 標準ライブラリでは、値の不在を正常系として返す API が多く存在する。

2.1 comma ok: (T, bool)

os.LookupEnv や sync.Map.Load と同じように、 「値」と「存在フラグ」を返す。 

func (r *UserRepo) LookupByID(ctx context.Context, id string) (*User, bool, error) {
    u, err := r.getByID(ctx, id)
    if err != nil {
        if IsNotFound(err) {
            return nil, false, nil
        }
        return nil, false, err
    }
    return u, true, nil
}

参照: os/env.go (LookupEnv), sync/map.go (Map.Load)

2.2 Option 型

samber/mo の Option[T] と同じく、値がある / ないを型で表現する。 

type Option[T any] struct {
    present bool
    value   T
}

func Some[T any](v T) Option[T] { return Option[T]{present: true, value: v} }
func None[T any]() Option[T]    { return Option[T]{} }

func (o Option[T]) IsSome() bool      { return o.present }
func (o Option[T]) IsNone() bool      { return !o.present }
func (o Option[T]) Get() (T, bool) { /* ... */ }

参照: samber/mo/option.go

2.3 存在確認 API の分離

redis.Exists や viper.IsSet と同じく、取得とは別に存在確認用の API を提供する。 

func (r *UserRepo) Exists(ctx context.Context, id string) (bool, error) {
    var exists bool
    err := r.db.QueryRowContext(ctx,
        "SELECT EXISTS(SELECT 1 FROM users WHERE id = $1)", id,
    ).Scan(&exists)
    return exists, err
}

参照: go-redis/commands.go (Exists), spf13/viper/viper.go (IsSet)

2.4 空コレクションを返す

mongo の Find や database/sql の Rows と同じく、 条件に合うものが 0 件でも nil ではなく空コレクションを返す。 

func (r *UserRepo) List(ctx context.Context) ([]User, error) {
    rows, err := r.db.QueryContext(ctx, "SELECT id, name FROM users")
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var users []User
    for rows.Next() {
        // ...
    }
    return users, rows.Err() // 0 件でも []User{}
}

参照: mongo-go-driver/mongo/collection.go (Find), database/sql/sql.go (Rows)

2.5 番兵値

strings.Index が見つからない場合に -1 を返すように、 値の不在を特殊な値で表現する。 

idx := strings.Index("hello", "z")
if idx == -1 {
    // 見つからない
}

参照: strings/strings.go (Index), go-redis/commands.go (Exists)

2.6 Null 型

database/sql.NullString のように、Valid フラグを持つ型で「値がある / ない」を表現する。 

var ns sql.NullString
if !ns.Valid {
    // 値がない
}

参照: database/sql/sql.go (NullString)

2.7 http.NotFound

HTTP レイヤーでは、エラーを一切使わず http.NotFound 関数で 404 レスポンスを書き込む。 

http.NotFound(w, r)

参照: net/http/server.go (NotFound, NotFoundHandler)

3. インターフェース層で NotFound を実装側に押し付ける

ent や gorm では、Get メソッドが NotFound エラーを返すという契約がインターフェースとして形成されている。 呼び出し側は、実装がどのエラー型を使っていても IsNotFound のような横断関数で判定できるようにする。

3.1 インターフェース契約

UserStore のようなインターフェースを定義し、 Get / Exists / Lookup のシグネチャで「存在しない」をどう表現するかを契約する。 

type UserStore interface {
    Get(ctx context.Context, id string) (*User, error)
    Exists(ctx context.Context, id string) (bool, error)
    Lookup(ctx context.Context, id string) (*User, bool, error)
}

参照: ent/entc/integration/ent/client.go (UserClient.Get), gorm/finisher_api.go (First/Last/Take)

3.2 センチネル契約

実装側が ErrNotFound を %w でラップして返す。 

func (s *RedisUserStore) Get(ctx context.Context, id string) (*User, error) {
    val, err := s.rdb.Get(ctx, "user:"+id).Result()
    if errors.Is(err, redis.Nil) {
        return nil, fmt.Errorf("redis store: %w", ErrNotFound)
    }
    // ...
}

参照: redis.Nil

3.3 型付きエラー契約

実装側が *NotFoundError を直接返す。 

func (s *PostgresUserStore) Get(ctx context.Context, id string) (*User, error) {
    return s.repo.GetByID(ctx, id) // *NotFoundError を返す
}

参照: ent/entc/integration/ent/client.go, ent/entc/gen/template/base.tmpl (NotFoundError)

3.4 自己申告契約

実装側が独自のエラー型を定義し、NotFound() bool を実装する。 

type articleNotFoundError struct{ ID string }

func (e *articleNotFoundError) Error() string { return "..." }
func (e *articleNotFoundError) NotFound() bool { return true }

3.5 シグネチャで強制

Exists / Lookup のようなシグネチャをインターフェースに含めることで、 実装側に「存在しない」をどう扱うかを強制する。

参照: sync/map.go (Map.Load), os/env.go (LookupEnv), viper/viper.go (IsSet), go-redis/commands.go (Exists)

3.6 横断判定 IsNotFound

k8s.io/apimachinery/pkg/api/errors.IsNotFound と同じく、 センチネル、型付きエラー、自己申告型の 3 系統を一つの関数で判定する。 

func IsNotFound(err error) bool {
    if errors.Is(err, ErrNotFound) {
        return true
    }
    var nf *NotFoundError
    if errors.As(err, &nf) {
        return true
    }
    var reporter NotFoundReporter
    if errors.As(err, &reporter) && reporter.NotFound() {
        return true
    }
    return false
}

参照: k8s.io/apimachinery/pkg/api/errors/errors.go (IsNotFound)

3.7 conformance 契約テスト

database/sql driver tests のように、同一インターフェースを実装する複数の実装に対して 同じテストを適用することで、契約を守らせる。 

func AssertUserStore(_ UserStore) {}

func TestContracts(t *testing.T) {
    AssertUserStore(NewRedisUserStore(rdb))
    AssertUserStore(NewPostgresUserStore(repo))
}

参照: database/sql driver tests

5. 推奨と使い分け

5.1 デファクト・スタンダードな選択

Go における「見つからなかった」のデファクト・スタンダードは、センチネルエラーである。 var ErrNotFound = errors.New("not found") のように、 パッケージレベルで定義された値を errors.Is で判定するのが最も一般的である。 

var ErrNotFound = errors.New("not found")

if errors.Is(err, ErrNotFound) {
    http.Error(w, "not found", http.StatusNotFound)
}

これは database/sql.ErrNoRows、os.ErrNotExist、io.EOF、 gorm.ErrRecordNotFound、mongo.ErrNoDocuments、redis.Nil などと同じ形である。

ただし、リソース名や ID などの詳細を含めたい場合は、 ent や k8s/apimachinery のように型付きエラーを使い、 errors.As で取り出す。さらに Is メソッドで ErrNotFound と等価にすることで、 呼び出し側は errors.Is(err, ErrNotFound) でも判定できるようにする。 

type NotFoundError struct {
    Resource string
    ID       string
}

func (e *NotFoundError) Error() string {
    return fmt.Sprintf("%s %s not found", e.Resource, e.ID)
}

// センチネル ErrNotFound との等価性を宣言
func (e *NotFoundError) Is(target error) bool {
    return target == ErrNotFound
}

// フィールドが必要な場合は errors.As で取り出す
var nfe *NotFoundError
if errors.As(err, &nfe) {
    fmt.Println(nfe.Resource, nfe.ID)
}

HTTP 層への橋渡し

ドメイン層の NotFound エラーを HTTP レスポンスに変換するのは「エラー表現」ではなく「使い方」の話である。 http.NotFound 関数や、ToHTTPStatus のような変換関数を使う。 

func ToHTTPStatus(err error) int {
    switch {
    case errors.Is(err, ErrNotFound),
        errors.Is(err, sql.ErrNoRows),
        errors.Is(err, fs.ErrNotExist),
        errors.Is(err, redis.Nil):
        return http.StatusNotFound
    default:
        return http.StatusInternalServerError
    }
}

参照: k8s.io/apimachinery/pkg/api/errors/errors.go, net/http/server.go

推奨:

  • 小規模〜中規模のパッケージ、ライブラリ → var ErrNotFound = errors.New("not found")
  • 大規模アプリ、リソース名や ID を含めたい → NotFoundError 型 + errors.Is/errors.As 対応
  • 呼び出し側を統一したい → IsNotFound(error) bool のような横断判定関数を提供する

5.2 使い分けの指針

  • ドメイン/データ層の失敗を呼び出し側に知らせたい → センチネルエラーまたは型付きエラー。
  • エラーに原因やリソース名を含めたい → 型付きエラー (NotFoundError)。
  • マイクロサービス/外部 API でエラーを分類したい → ErrorCode() / ErrorFault() 付き。
  • 存在確認だけで「無い」ことを正常値としたい → comma ok / Option / Exists / MaskNotFound。
  • 一覧取得 → 空コレクションを返す。
  • HTTP 層の最終出力 → http.NotFound または ToHTTPStatus。
  • 実装を差し替え可能にしたい → インターフェース + IsNotFound による統一判定。
  • インターフェース契約を守らせたい → AssertXxx による conformance テスト。

6. まとめ

Go における「見つからなかった」の表現は、単一の正解ではない。 errors.Is / errors.As を中心としたエラー型の表現、 comma ok、Option[T]、空コレクション、番兵値、Null 型など、 エラー型を使わない表現も豊富にある。

デファクト・スタンダードは var ErrNotFound = errors.New("not found") のセンチネルエラーである。 しかし、実際のコードではライブラリやレイヤーに応じて適切なパターンを選び、 呼び出し側が「見つからない」ことを予測可能に検知できるようにすることが重要である。

インターフェースを挟むことで「NotFound の表現」を実装側に押し付け、 呼び出し側をシンプルに保つこともできる。 契約を守らせるためには、database/sql driver tests のような conformance テストが有効である。
